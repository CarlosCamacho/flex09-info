TO ALL SCREDITOR III PURCHASERS
	(LAST MINUTE NOTES)


(TM) in PRINT-MERGE

The (TM) replacement string in the	PRINT-MERGE	COMMAND	is
not available in this version of	SCREDITOR	III.	The	(LM)
replacement string works as described, however.


TUTORIAL CASSETTE

We are now writing a complete TRAINING and USER'S GUIDE	for
SCREDITOR III. Since the tutorial cassette mentioned in	our
literature will be used in conjunction with the	GUIDE,	and
must follow	reasonably	closely	with	the	GUIDE,	we	are
developing both simultaneously. We will be shipping you both
of them at no charge when they are available.


COMING UPDATES

We are already working on the first update to SCREDITOR III.
Included in the update will be the (TM)	replacement	string
in the PRINT-MERGE COMMAND.

Also, we are adding a number of COMMANDS	and	OPERATORS	to
improve the handling of paragraph and	line	indenting.	The
CONVERT UPPER and CONVERT LOWER OPERATORS will be deleted to
add INDENT LINE and UNDENT LINE OPERATORS.

In addition, we are changing the CHANGE,	KILL	LINES,	SAVE
LINES and	a	few	other	COMMANDS	to	allow	the	type	of
optioning which exists with the MOVE and COPY COMMANDS.

When the updated program is available, you will be notified.
We expect the update to cost you about ten dollars, covering
basically the price of mailing and handling. When the update
is ready, you will have to send	us	the	ORIGINAL	DISK	to
receive the new version of SCREDITOR III.


PROPORTIONAL PRINTER DRIVERS

We are now working on the proportional printer	drivers	for
SCREDITOR III. When they	are	available,	they	will	be	a
user-installed retro-fit which will work in a manner similar
to CONGEN. In fact, there will be a PPDGEN	program	on	the
disk to	customize	the	drivers	for	particular	printers.
Frankly, we would have had the drivers done by	now	but	we
couldn't decide how we wanted to handle multi-column text.


HELP FILE VERSUS REFERENCE CARD

Which do you want? We need to know before the first	upgrade
disk is ready. A HELP COMMAND would be fairly easy to	build
into SCREDITOR III (we did it and then	took	it	out),	and
could be really handy, but there are drawbacks.

First, a HELP COMMAND would not get lost like an	OPERATOR'S
REFERENCE CARD, but would	take	another	chunk	of	program
code. Also, the HELP COMMAND would require that	the	system
disk or working disk contain the help message file.	Such	a
file will take about forty or fifty sectors	of	disk	space
with the current SCREDITOR III command set. The HELP COMMAND
itself will take several hundred	bytes	of	program	space,
meaning longer load times and less edit buffer.

Take a moment to fill out the	enclosed	registration	sheet
and get it back to us. Indicate your preference. We want	to
know how you, the users, feel before we decide on this one.


BUGS, GREMLINS, GLITCHES, ETC...

With any program this size, there are bound to be a few bugs
cropping up somewhere along the line. If you run	into	any,
please let us know. We have been using SCREDITOR III for six
months now in-house, and still trip over one every once in a
while. Of course, with a program which is	written	entirely
in assembly language, and	is	ELEVEN	THOUSAND	lines	long
(about 375,000 characters in	ten	files!),	there	is	some
SLIGHT possibility of an error or two being overlooked!


FINALLY...

my recent	illness.	I	hope	that	SCREDITOR	III	will	be
everything you hoped it would be, and	thank	you	for	your

TO ALL "PROGRAMMED" DISPLAY USERS -

If you are using a VDU which uses a	scroll	register	(such	as
the Smoke Signal VDB-1, Gimix 80x24, Percom Electric Window,	or
F&D display board), and your system	display	handling	routines
use the scroll register for screen scrolling, you must make	one
additional change	to	the	overlay	source	code	which	SYSGEN
produces.

Even though this source code will properly exercise your	board,
the SCREDITOR II does not use the scroll register,	but	rather,
sets it so that the last line on the display is	physically	the
highest line in memory and scrolls the screen by re-writing	all
characters on the screen offset by one line whenever necessary.

Because of this, your screen handlers will probably think	lines
on the screen are in a different	position	than	they	actually
are when you exit the SCREDITOR II,	either	from	a	fatal	DOS
error, abort, closing, exit to system monitor, etc...

In order for your handlers	to	know	where	the	lines	on	the
screen really are, you should	patch	the	keyboard	restore	or
echo restore routines generated by SYSGEN to include	a	JSR	to
your VDU init routines. For many handlers a	"print-top-of-form"
call will work. BE	SURE	THE	INIT	ROUTINE	YOU	CALL	RETURNS
CONTROL TO THE SCREDITOR	II,	AND	THAT	THE	KEYBOARD	RESTORE
ROUTINE YOU PATCH STILL ENDS IN RTS (SEE EXAMPLES BELOW).

For Gimix-bug III users, the following code will work:

	OLD CODE -	NEW CODE -

	RTS	(END OF KBDRES)	SWI
CALL GIMIX-BUG III
	 FCB	23	WITH TOP OF FORM
	 RTS
THEN RETURN

For SSB VDB-1 users utilizing the on-board	ROM,	the	following
will work:

	OLD CODE -	NEW CODE -

	RTS	(END OF KBDRES)	JSR	$CC09	CALL INIT ROUTINE
	 RTS

For users where top-of-form will do	the	trick,	the	following
code should work:

	OLD CODE -	NEW CODE -

	RTS	(END OF KBDRES)	LDAA	#$C	GET TOP OF FORM
	 JSR	PUTCH	RESET VDU
	 RTS
AND RETURN

In all cases, no registers need to be preserved.

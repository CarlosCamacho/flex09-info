DATAMAN source code is supplied on either 2-5 1/4" or 1-8" FLEX compatible disks.
These original disks should be copied and the original disks should be stored in a safe place.
The user must supply the needed utilities and TSC programs listed in the section 'HARDWARE & SOFTWARE REQUIREMENTS'.


The DATAMAN disk(s) 'DMUNIV' includes all the source code for DATAMAN along with two system generator programs.
It is necessary to first build a DATAMAN 'system' disk.
This disk called 'DMUNIVC' includes the FLEX utilities needed for DATAMAN operation, TSC extended Basic,
the programs 'CSORT.CMD' and 'SRTMRG.SYS' from the
TSC sort/merge package, a file called 'SYSTEM.GEN', and the compiled DATAMAN programs.
If you are using a single sided, single density 5 1/4" disk system you will need to make two system disks because the
complete DATAMAN system will not fit on one disk.
Before putting any DATAMAN programs on this disk, the system disk should look like this...

CREATING THE
'SYSTEM.GEN' FILE
.FI
.LM 55
The 'SYSTEM.GEN' file must be put on each DATAMAN system disk (DMUNIVC).
This file is loaded by each DATAMAN program module and it includes the necessary information to allow DATAMAN
to work with your system terminal/CRT and printer.
This feature allows you to configure DATAMAN to your system without having to modify all the DATAMAN program modules.


To get the system disk up the first time it is suggested that you load TSC extended Basic (hereafter called Basic) then load the
program 'SYS-AUTO.BAS' found on the DATAMAN disk 'DMUNIV'.
Put your disk 'DMUNIVC' into your drive '0' and 'RUN' the 'SYS-AUTO' program.


You will first be asked to input decimal codes for your terminal cursor control.
These include 'home up', 'erase to end of field', 'cursor right', and 'cursor down' or 'line feed'.
It is important to input a '0' for any unused code!
If you are using a system terminal without some of these cursor funtions, like a printer terminal, simply enter '0' for all the
'TERMINAL' prompts.
It is suggested that if you are using a 16 X 64 CRT that you also enter a '0' for all the 'TERMINAL' codes.


The next section of the program prompts for printer codes.
DATAMAN supports the new small printers that print a variety of character sizes under software control.
These printers will print both 10 cpi for 80 collums and 16.7 cpi for 132 collums on 9 1/2" pin feed paper.
One such printer of this type is the CENTRONICS 737 printer.
This printer uses a decimal '27' followed by a decimal '19' to put the printer in the 10 cpi print mode.
These are the codes that are being asked for in this section.
Consult you printer manual for these codes.
If you are using a printer that has only 80 print positions, enter '0,0' for both the 80 and 132 character prompts.
You will only be able to utilize the 80 character reports generated by the DATAMAN 'REPORT WRITER'.
If your printer only supports only one print size but loads paper wide enough to print 132 columns, you still need
to enter '0,0' for both the 80 and 132 prompts.
You will be able to print both 80 and 132 column reports, but you will have to remember to change paper.


The codes for 'Expanded Print' are for printers which support expanded type that is twice as wide as the regular character width.
The code required is to 'start' the elongated print.
DATAMAN takes care of switching the printer back to the 'regular' print mode.
For further information, see section 25 on 'CUSTOMIZING DATAMAN'


The last section of 'SYS-AUTO' requires you to input the 'drive numbers' of your system.
Make sure you use a '0' for any unused data as before.
In a 2 drive system, the input to this prompt would be '0,1,0,0'.
A three drive system would be '0,1,2,0' and a four drive system would be '0,1,2,3,'.
If more than four drive numbers are required, consult section 25.2.3.


Once all the program prompts have been entered, make sure that your DATAMAN system disk 'DMUNIV' is in drive 0 and hit 'RETURN'.
When the program has generated the 'SYSTEM.GEN' file on drive 0, you will return to Basic with a 'READY'.
Confirm that the 'SYSTEM.GEN' file has been written on your 'DMUNIV' disk.
This file should be at least 1 sector long.
If you make a mistake while running 'SYS-AUTO' simply re-run the program.
If you are making more than one system disk, simply copy the 'SYSTEM.GEN' file to the other system disks.

It is now time to start compiling the DATAMAN programs on your 'DMUNIV' disk.
Load Basic and load the DATAMAN menu 'DATAMAN.BAS' from the 'DMUNIV' disk.
If you 'LIST' this program you will see that the 'WARM START' is located at line 1170.
When DATAMAN program modules are finished running, most of them end with a statement that looks like this...
.sp1
.lm 65
.NF
2100	CHAIN "0.DATAMAN.BAC"	1170
.LM 55
.FI
.sp1
This returns program execution to the program 'DATAMAN.BAC' at line 1170.
This allows you to use any line number in the program 'DATAMAN' below line 1170 to set conditions, load time/date programs, etc.
Any line below line 1170 will usually	only be executed the first time the program is run.
For instance, DATAMAN assumes that in your FLEX system startup you 'ASN W=1,S=0'.
If for some reason you don't use this assignment of your drives, then you might want to add a line of code that looks like
this in the program 'DATAMAN'...
.sp1
.lm 65
.NF
1090	EXEC, "ASN W=1,S=0"
.LM 55
.FI
.SP1
If you did this, you would also have to add the FLEX utility 'ASN' to your system disk 'DMUNIVC'.


If you have made any changes in the program 'DATAMAN' make sure you 'SAVE' it back to the 'DMUNIV' disk then 'COMPILE' the program to
drive '0' using the same name (COMPILE "0.DATAMAN.BAC").


It is a good idea to run a check to make sure your 'SYSTEM.GEN' file is working for your system terminal/CRT.
To do this, bring up the DATAMAN menu by making sure that your system disk is in drive '0' and type RUN "0.DATAMAN.BAC".
On a system terminal with cursor control characters the display should look like this...
.pg
On a system terminal without cursor control the menu should look like this...
.sp24
If you are having problems with these displays, go back to the section on creating the 'SYS-AUTO' file and make the file again making
sure that you input the correct codes and that they are 'DECIMAL' and not 'HEX'!


Next, choose a menu selection, say '1' for 'CREATE A DATABASE'.
Notice that the 'ACTION HEADER' changes showing
that the computer is attempting to load the program '0.BSDMAN.BAC'.
The computer will not find this program because you have not yet compiled it to the system disk yet.
The system terminal 'bell' will sound (if you have one) and an error message will appear telling you that the program
was not found.
After a short pause, the menu will be re-written on the system terminal/CRT.
Error messages in the DATAMAN system always start with a 'bell' to get the operators attention.


After you have played with the menu for a while, it is time to compile the rest of the DATAMAN program modules to the
system disk 'DMUNIVC'.
For each program, load it into Basic from the 'DMUNIV' disk and compile it to the 'DMUNIVC' system disk.
For instance, if you have the system disk 'DMUNIVC' on drive '0' and the source disk 'DMUNIV' on drive '1', to compile
the DATAMAN program 'BSDMAN' you would 'LOAD "1.BSDMAN.BAS"' then 'COMPILE "0.BSDMAN.BAC"'.
Do this for all the DATAMAN program modules.
.pg
As mentioned before, those users that have 5 1/4" single sided, single density disk drives will have to use two system disks and
split the DATAMAN program modules between them.
When doing this, make sure that each system disk contains the DATAMAN menu 'DATAMAN', the 'SYSTEM.GEN' file, as well as the FLEX
programs and utilities needed.
It should be noted that the two TSC sort/merge programs need only to be on the system disk which contains the DATAMAN
sort editor 'STDMAN' because this is the only program that uses these two TSC sort/merge programs.
Basic should also be left on all system disks.
This is because that some programs re-load Basic.
For example, when you run the DATAMAN sort editor 'STDMAN', Basic gets blown away when 'STDMAN' loads the TSC sort/merge programs.
DATAMAN keeps control of the system through a FLEX 'EXEC' file written to drive '1' and re-loads Basic and the DATAMAN menu
when all sorting is done.
If Basic is not found on the DATAMAN system disk, DATAMAN will lose control and you will drop into FLEX.
You will then have to find BASIC on a disk, reload it into memory and 'RUN "0.DATAMAN.BAC"'.
There are also other times when DATAMAN re-loads Basic.


You should now be ready to try DATAMAN out with a test database.
This will give you an idea of how DATAMAN programs work together to change and manipulate information.
The next section 'THE THEORY OF DATABASE MANAGEMENT' will give the
newcommer to database management a foothold and give
both the newcommer and the 'pro' an idea of how DATAMAN is set up.
This section will only take a few miniutes to read, then you can try out DATAMAN in 'THE DATAMAN SAMPLE RUN'.

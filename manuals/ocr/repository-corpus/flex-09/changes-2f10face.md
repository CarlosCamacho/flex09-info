# CHANGES

> Source: `flex-09/distributions/FL_504F - Frank Hogg FLEX 5.04 System and Source Disk.zip!FL_504F.DSK!CHANGES.TXT`  
> Method: FLEX disk extraction

OCR and media-decoding errors may remain.

Changes made to FHL FLEX for version 5.0:4

1. Smooth scrolling capability added. Jump scroll capability is
	retained, with a 50% speed increase.

2. Control-V causes the output driver to switch scroll rates.
	Control-V is followed by a one-character parameter, from
	A to F.	A specifies smoothes scrolling and F specifies full
	jump scroll.	D, E, and F are equivalent for all modes except
	32x16.

3. Control-W is the code to generate status lines (it was Contol-C
	previously.)	The number of status lines is limited to four.

4. Some bugs in the handling of status lines and locked lines were fixed.
	If every non-status line on the screen is locked, the locked status
	of the lines is ignored.	The lines become locked again if an
	unlocked status line is freed up with Control-D.

5. The bug which prevented Stylo from recovering from a disk error has
	been corrected.

6. EXT has been extensively revised.	The manner in which the video
	terminal should be connected is now different.	The RS232 input
	(from the terminal to the computer) should be connected to pin 1 of
	the RS232 plug, called "CD" in the Color Computer Service Manual
	and Operation Manual.	Pin 2, called "RD" and previously used for
	RS232 input, should now be connected to the DTR lead from the
	terminal.	The new EXT uses this signal to implement true hardware
	handshaking.

	As a result all of the printer delay parameters have been removed.
	They are no longer needed as the DTR signal causes the necessary
	delays.	The calling line for EXT is now:

	EXT,n,p1,p2,...pn,m,q1,q2,...qn,ec

	where

	n	(decimal) is the number of characters in the sequence to

disable printer pass-through on the terminal.

	p1-pn (hex) are the characters in the sequence to disable printer

pass-through.	This sequence is also sent when EXT is run

to initialize the terminal.

	m	(decimal) is the number of characters in the sequence to

enable printer pass-through on the terminal.

	q1-qm (hex) are the characters in the sequence to enable printer

pass-through.

	ec	(hex) is the character generated by the input routine if

a transition on the input line is detected by the status

routine.	If ec is 0, no character will be generated,

although true status will be returned.

	A maximum of 12 characters may be supplied for each sequence.

	The default calling sequence, for Televideo 910 terminals, is

	EXT,3,1B,61,0E,1B,60,1B

	If any of the defaults are changed, all of the parameters must be
	entered.

	Note the "0E" added to the default disable sequence.	This code
	disables the XON/XOFF software handshaking on the 910.	The new
	EXT is sensitive to any transition on the input line for the
	purpose of interrupting printing (it is no longer necessary to use
	the BREAK key) and the XOFF generated when the buffer is full would
	interrupt output, requiring an ESCAPE to be input.

	For use with a TVI910 and u82A, pin 11 of the u82A should be connected
	to pin 20 of the TVI910 for proper handshaking.

	EXT is also changed so that it will not run if MEMEND is not B7FF.
	This condition applies if in a 32 by 16 mod, if already in EXT, or
	if MCOMMAND or something that changes MEMEND hs been run.	EXT prints
	the error message "CANNOT BE RUN FROM THIS MODE" if this occurs.

7. INT has been modified so that it will not run if MEMEND is not equal to
	BFFF.	This will occur if MCOMMAND, etc. is run from EXT.	The error
	message is "CANNOT BE RUN - MEMEND CHANGED".

8. Control-Q does not change the screen color between white and green,
	like it did at Rainbowfest.	SETUP must be used to do this.	Setup
	probably has the code to do this in it, but it should be checked.
	It needs to be documented.

	I looked at the version of SETUP I'm using and it has nothing for
	this.	That might not be the right version, though - check and see
	if you have a source for it.

9. The Xcommands (X3216BW, etc.) have been kludged up so they will not
	crash the system.	Please do not state that verbatim in the user
	documentation.	Anyway, you cannot change the hi-res mode (by running
	an Xcommand) unless you are in a hi-res mode (not EXT.) Also,
	MEMEND must not be changed.	The error message is "CANNOT BE RUN IN
	THIS MODE."

10.DBASIC has also been modified so it can only be run from a non-32x16
	hi-res mode with MEMEND unchanged.	Message is "CANNOT BE RUN FROM THIS
	MODE."

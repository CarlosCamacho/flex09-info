Preliminary documentation

NOTE: This package needs a 80 by 24 line terminal with direct cursor
	positioning and a home and clear facility to run. Clear to
	end of line and screen are desirable but not essential.

	A minimum of 48K user RAM is needed to run the package.

The AP system is designed to play any adventure game that can be
built within the system rules. This is possible due to a complete
separation of game and program. Adventure games are held in text
files on disk and loaded into the adventure interpreter to be run.

This package also includes an adventure editor to allow you to
create your own adventures or modify those supplied with the system.

At present the games (in order of difficulty) are:

.nf
ALASKA	Alaskan Exploration during the goldrush.
NITEMARE	Science Fantasy mission on an alien planet.
SHAKTRY	Fantasy adventure in a magical maze.


The system consists of a suite of programs:

AP		The adventure interpreter.
APEDIT	Adventure game editor.
APLIST	Adventure game lister.
APTAB	Prepares a map grid to design adventures on.

CONFIG	Used to set up the programs to suit your terminal.
.fi


Each game is held as two Flex text files. Both filenames differ
in the extension only. .DES holds title screens and the adventure
map. .ADV holds all objects and menaces that may be met in the
game. When you save a game, another .ADV file is created using the
name you give. Saved files cannot be deleted by AP, so you must
periodically erase the junk from your data disk.

All programs honour FLEX system and work drive settings and will
run in a single disk system. Current TTYSET pause and width values
are reset during the run but are restored on exit from the program.

Getting started.

As issued, all the programs are supplied in an incomplete
form with .BIN extensions. Before you can run them you must set up
your terminal and printer descriptions.

TTYSET is used to define the three special keys that control input;
<backspace>, <line cancel>, and <tab>.	CONFIG sets up device-dependant
output sequences to control the terminal screen and the printer.

First run TTYSET to set the BS, DL, and TB values (in hexadecimal) if the
values generated by your favourite key assignments differ from the
defaults.	When you are satisfied with these assignments, include the
TTYSET call in your STARTUP.TXT file.

Make sure that PRINT.SYS is loaded before continuing, as CONFIG, APLIST,
and APTAB use it for printer output.	Include GET 0.PRINT.SYS in your
STARTUP.TXT file if it is not there already.

Now run CONFIG. This program asks questions about the control strings
needed to control your terminal and printer.
The minimum terminal requirements are the 'Home and clear' and cursor
movement sequences.
All input is in Hex I'm afraid, but
the prompts are self explanatory.
The essential printer control sequences are page throw, set and cancel
condensed printing, and set and cancel enlarged printing.
If you have a choice of modes (the Epson gives this choice), make sure
that you pick modes that are

not
cancelled by line or page throws.
All printouts are designed for 11" paper (66 lines deep) and 9.5" wide
(80 columns at 10cpi). Both reports use condensed mode to get 132 columns
on the paper. The programs generate CR/LF sequences at line ends;
if your printer auto-linefeeds you will get double spacing.
Dont worry if you make
mistakes as CONFIG will test your parameters and allow you to
re-do them over and over til you are happy, before saving them to
disk with a .VDU extension. When you run the program you may either
start with the default values (for DEC VT52 type terminals and Epson MX
printers) or load an existing .VDU file.

Using the system.

To run an adventure, run AP. No parameters are needed. The program
will identify itself and then ask for the adventure name. Two
title screens are displayed (hit any key when you have read each
screen) and then you are asked if you want to load a saved adventure.
Answering 'n' loads the starting state for the adventure. If you
answer 'y' you will be asked for the name of your saved state.
If you want to abandon the run, <cr> in place of either filename will
abandon the program.

Whenever an adventure ends due to sudden death, quitting, or even
winning the game you will be asked whether you want to play another
game. Answer 'n' to exit to FLEX.

Once into an adventure, the program is self explanatory. If you
get confused you can always type 'inst' to get two screens of
instructions or 'verb' to see the verbs it understands.

There are three special keys defined via TTYSET. Their meanings are:

Creating your own adventures.

The remaining programs are used to create and modify adventures.

APTAB is a design aid. It prints a 10 by 10 numbered grid that is
a representation of the internal map in AP. Use it to draw your
map, place things in locations, and link locations via exits and
portals. It will ask for the name of an adventure to use as a heading.

APLIST is used to list adventures. You can use LIST but APLIST gives
a formatted listing as well as translating object types etc. You
will find it helpful to list an adventure you have solved before
designing your own.

.ne 11
APEDIT is a large multifunction program that:

	Edits/creates the title screens
	Sets up win conditions
	Edits the map
	Edits the list of objects
	Edits the list of menaces

	Allows the resulting adventure to be inspected in a similar
	location display to that used by AP so you can check out
	your map without having to fight your way round it.

	Load the adventure

	Reorganise the tables. Necessary whenever the accumulated text

to be written to disk and then reloaded in minimum space.
	Title screen amendment. The screen is overtyped to change it.
	Descriptive (second title) screen amendment.
	Win condition amendment.
	Start position amendment.
	Object amendment.
	Monster amendment.
	Location amendment.

Object and monster amendment work from a menu of the list contents.
Select the n th item:
	+n adds a new item as no n in the list
	?n displays the n th item
	/n shows the n th item for overtyping.
	-n deletes the n th item from the list.

.ne 7
Location amendment works via a 10 by 10 grid. Each grid entry is the
numeric 'location state' value (see below).
Select location n:
	/n shows the n th location for overtyping.
	?n displays the n th location.

Locations cannot be added or deleted.

Adventure changes are applied via filling in formatted screens.

New contents are set up by typing into each field. End by typing <return>.

A field is left 'as is' by typing <return> as the first character.	All
default values are accepted though not necessarily sensible.

A field is erased by typing <space><return> as the first two characters.
Fields can start with spaces but this is not usual or sensible.

Changes are applied by overtyping the existing contents. Use <backspace>
and <line cancel> to erase mistakes within a field. Small corrections are
applied by using the <tab> key to copy the field to the point where
changes are made and then overtyping. However do remember that the new
contents will end	wherever you type <return> - use <tab> to copy the
remainder of the old contents to the right of your correction.

How an adventure is set up.

.ul
Fixed data.

Title screens. Both initial screens are always present but may be
blank - however even a blank screen will be displayed. Each screen
has 23 lines of 80 characters.

Win conditions. A win is defined as arriving at a specified location
with certain specified objects. Some may have been left there previously.
Only one win position may be given. It must be accessable on the map.
Up to 10 objects may be quoted. List the names used to manipulate
them in lower case. At least one must be entered. You must also say
how many of the objects must be present - so a win can be achieved
by presenting any n of the objects listed. 1 of 1 is probably the
usual win condition.

NOTE an adventure cannot be saved until win conditions have been set
up.

Start position. Nominate the starting location within the map. The
win position may be the starting point or anywhere else in the map.

Locations. 100 locations numbered 1 to 100 together make up the
adventure map. They are numbered by position in the locations list.
Locations are regarded as appearing on a 10 by 10 grid for map
creation purposes and wandering monster movement. The grid is numbered
from 1 in the top left corner to 100 in the bottom right working along
the rows. Note that there are no assumptions built into the direction
vectors of each location that 'north' necessarily moves up a row etc,
although this is a usual convention. Nor need 'south' necessarily
be the reverse of a preceeding 'north' (useful in mazes !).
